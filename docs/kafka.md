# Kafka

Между `app1` и `app2` нет HTTP и нет общего WebSocket. Сокет игрока живёт только в памяти того процесса, к которому его подключил nginx. Поэтому `emit` на первом процессе второго игрока не видит.

После записи хода в Postgres `MatchesService` публикует снимок матча в топик `game.events`. Ключ сообщения — `matchId`, ходы одного матча остаются в одной партиции и идут по порядку.

У каждого процесса свой consumer group: `tic-tac-toe-<INSTANCE_ID>`. Одна группа на всех забрала бы партиции поровну, и часть матчей не дошла бы до инстанса, где сидит соперник. Своя группа значит: каждый процесс читает все события и отдаёт их в сокет, только если этот игрок подключён локально.

Брокер в compose — Apache Kafka 3.8, KRaft, без ZooKeeper.

- контейнеры ходят на `kafka:29092`
- процесс на машине — на `localhost:9092`

Топик создаётся при старте сервера, 3 партиции, replication factor 1.

Если публикация не удалась, ход уже лежит в базе. Игрок, чей сокет на этом процессе, снимок всё равно получит ответом на `game.move`. Соперник увидит его после своего переподключения: состояние читается из Postgres.
